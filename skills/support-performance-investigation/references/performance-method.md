# 性能排查方法

## 先定义问题

记录可观察症状、影响用户或操作、问题时段和时区。优先选择同业务、同流量形态、同版本的正常时段作基线；如果期间有发布、配置、数据规模或流量变化，把差异单独列出。

## 指标层次

从外到内核查：

1. 用户层：成功率、端到端延迟、受影响范围。
2. 服务层：请求率、错误率、p50/p95/p99、队列等待。
3. 工作负载层：慢接口、慢任务、项目/用户/仓库贡献者。
4. 依赖层：数据库、缓存、存储、外部服务。
5. 资源层：CPU、内存、I/O、网络、连接/线程/文件句柄池。

百分位数必须同时给样本数。长连接、流式响应、下载、健康检查和后台任务应按语义分组，避免混在普通请求中。

## 因果判断

一个可信瓶颈同时满足：坏时段显著变化、时间上先于或同步于症状、能够解释影响面、基线中不存在或显著较弱，并且没有更强反证。仅“数值很高”或“同时出现”只能作为线索。

## 下一步

每个高优先级假设只给最小、优先只读的验证动作，写明预期结果和相反结果如何改变判断。优化建议与诊断步骤分开；没有根因证据时不要先给扩容结论。
