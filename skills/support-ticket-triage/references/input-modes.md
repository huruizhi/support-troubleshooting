# 输入路径细则

## quick

适用于用户已经粘贴正文、错误、截图文字、工程师判断或关键日志片段的情况。

1. 从现有内容提取症状、影响、时间、产品版本、已执行动作和直接证据。
2. 输出 `performance`、`incident` 或 `mixed` 初判，并把每个理由对应到用户提供的原句、错误或指标。
3. 将推断标为假设，将无法从现有内容确认的事项列为缺口。
4. 给出一个最小下一步。现有内容已经足以回答时直接结束，不调用工具，不创建目录。

用户希望“找出依据”时，在现有内容中完成证据定位；不要为了形式完整改走 MCP。

## mcp

适用于只有工单号、关键证据缺失，或用户明确要求获取和保存的情况。

1. 使用 MCP 当前工具 schema 支持的最短路径获取工单上下文。若工具支持按精确工单号直接读取上下文，则省略搜索；否则先精确搜索再读取上下文。
2. 先判断正文和附件目录是否足够。只有某个证据缺口会改变分类或下一步时，才读取对应附件。
3. 用户明确要求归档时，读取 [共享产物契约](../../../references/artifact-contracts.md)，保存原始返回、必要附件、证据索引和路由结果。
4. 工单不存在、认证失败或附件不可读时，报告一个明确 blocker，并保留已经取得的事实。一次失败不触发无界重试。

授权提示由宿主控制。skill 通过减少和合并数据请求降低交互次数，不能绕过宿主授权。

## local-log

适用于用户给出本地日志，或 MCP 返回大小限制的情况。

1. 确认本地路径、文件类型、大小、时间覆盖和时区。
2. 日志在本地读取和分析；MCP 仅在缺少工单元数据且该元数据会改变判断时使用。
3. 支持的 GitLab 日志按 [fast-stats 适配说明](../../../references/fast-stats.md) 调用包装脚本。参数必须来自当前 CLI help。
4. 日志尚未在本地时，只请求一次：请将文件下载到明确目录并提供路径。不要反复通过 MCP 传输同一大文件。

## 路径切换

- `quick → mcp`：现有证据不足，且工单号可用。
- `quick → local-log`：需要原始日志验证，且本地文件可用。
- `mcp → local-log`：附件超过 MCP 限制或本地分析更合适。
- `mcp → quick`：取得最小上下文后已经足以回答。

每次只发生有证据理由的一次切换，避免在路径之间往返。
